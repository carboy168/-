# V1.3-0 Contract Governance

## Version source

`version.ini` is the only application-version source. Python runtime, PyInstaller,
Inno Setup, the local build script, and Windows CI must consume that file rather
than declaring their own version.

## Engineering Knowledge compatibility

- `data/engineering_contracts.json` is the contract registry.
- `current_write_version` is the only version new packages may write.
- `readable_versions` is the complete allow-list for readers.
- Validation explicitly distinguishes `for_write=True` from compatibility reads;
  old readable contracts are never silently used as the current write format.
- A frozen schema is protected by canonical-JSON SHA256, so line-ending and
  formatting differences do not weaken or accidentally trigger the guard. It
  must never be edited in place.
- Additive or breaking contract changes require a new schema version and an
  explicit compatibility adapter. Unknown versions fail closed.
- This policy governs serialized structures only. Router candidates remain
  retrieval hints and never become evidence through compatibility conversion.

## Database boundary

V1.3-0 does not change the database schema or migration version. `route_logs`
already belongs to `db.init_db()`. Router logging may only insert into that table;
it must not execute DDL or attempt an implicit migration.

## Benchmark governance

`data/benchmark_manifest.json` is the inventory of engineering benchmark suites.
`python desktop_tools/benchmark_runner.py` validates every fixture and executes
the corresponding test modules. Adding a benchmark requires updating the
manifest; a fixture that is merely present is not considered executed.
